# 送客システム設計（ワンクリック送客＋送客数のリアルタイム共有）

> やりたいこと：
> 1. 先生が**ボタン1つ**で外部業者へ送客できる（資料請求・相談予約を含む）
> 2. **「今、何名送客したか」を送客先企業とリアルタイムで共有**できる
> 3. 1件ずつ追跡して、**成果報酬を正しく回収**できる
>
> 関連：医院カルテ＝[`05-clinic-profile-questions.md`](./05-clinic-profile-questions.md)（同意・差し込みの素）／ 送客先一覧＝[`01-routing-priority-master.md`](./01-routing-priority-master.md) §4

---

## 1. なぜ「ワンクリック」でできるのか

最初に**医院カルテ**で医院名・担当者・連絡先・お悩みを登録済み（[`05`](./05-clinic-profile-questions.md)）。
だから送客ボタンを押した瞬間、**入力はゼロ**。登録情報がそのまま送客先へ渡る＝本当にワンタップ。

> ※「同意_第三者提供=済」の先生のみワンクリック。未同意の人だけ初回に1回確認。

---

## 2. 全体構成（データの流れ）

```
   先生のLINE（Lステップ）
        │  送客ボタンをタップ（資料請求／相談予約／見積依頼）
        │  ① 同意チェック ② タグ付与 ③ 送客IDを発行
        ▼
   Lステップ「Webhook転送」でイベントを外部へ送信（リアルタイム）
        │
        ├──▶ 送客台帳（Googleスプレッドシート or DB）に1行追記
        │           │
        │           ▼
        │     Looker Studio：送客先ごとの専用ダッシュボード
        │     （今日／今月／累計の送客数をリアルタイム表示・閲覧専用）
        │
        ├──▶ 送客先へ即時通知（メール／Chatwork／LINE WORKS／Slack）＝すぐ対応
        │
        └──▶ 先生へ自動返信「受付しました。担当者からご連絡します」
```

**ポイント**：Lステップの **Webhook転送はフリープランからオプションで利用可**。ボタン操作をトリガーに、リアルタイムで外部へデータを飛ばせる（出典は末尾）。

---

## 3. 段階的な作り方（最善の進め方）

### フェーズA：まず安く早く（目安2〜4週間・低コスト） ← 推奨スタート

| 役割 | 使うもの | やること |
|---|---|---|
| 入口 | **Lステップ（回答フォーム＋Webhook転送）** | ワンクリック送客、友だち情報の差し込み、送客IDの発行 |
| つなぎ | **Make（または GAS=Google Apps Script）** | Webhookを受けて台帳に追記・通知を振り分け |
| 台帳 | **Googleスプレッドシート** | 全送客を1行ずつ記録（後述のスキーマ） |
| 共有画面 | **Looker Studio** | 送客先ごとに「自社分だけ」見える専用ダッシュボード |
| 通知 | **メール／Chatwork／LINE WORKS／Slack** | 1件来るたび送客先へ即時通知 |

➡ これで「**ワンクリック送客**」と「**送客数のリアルタイム共有**」は達成できる。

### フェーズB：本格化（成果報酬の精算まで自動化）

| 追加する役割 | 使うもの | やること |
|---|---|---|
| 送客先ポータル | **Airtable（Interface）または Supabase＋簡易Webアプリ** | 送客先が**ステータス（対応中→商談→成約）を自分で入力** |
| 書き戻し | **LステップAPI連携（プロプラン以上）** | 成約結果を先生のタグへ反映、追客を最適化 |
| 精算 | ポータル＋自動集計 | 成約に連動して**成果報酬を自動計算→請求書連携** |
| 認証 | ポータルのログイン | 送客先ごとにアカウント発行（安全な共有） |

> **最善の方針**：まず**フェーズAで実運用→効果を確認**し、送客先が増えて精算が煩雑になったら**フェーズBへ**。最初から作り込みすぎない。

## 4. 送客台帳のデータ項目（スキーマ）

1送客＝1行。`共有`列は送客先ダッシュボードに表示する項目。

| 項目 | 例 | 送客先に共有 | 用途 |
|---|---|:-:|---|
| 送客ID | R-20260620-0001 | ✓ | 一意キー・成果報酬の突合 |
| 日時 | 2026-06-20 14:32 | ✓ | 件数集計・対応スピード |
| 医院名 | ◯◯歯科 | ✓ | 送客先の対応 |
| 都道府県／市区町村 | 東京都／渋谷区 | ✓ | エリア判定 |
| 担当者名 | 院長 ◯◯ | ✓ | 連絡先 |
| 連絡先 | 電話／メール | ✓（同意者のみ） | 連絡 |
| お悩みカテゴリ | クラウドアポ帳 | ✓ | マッチング確認 |
| 送客先パートナー | iQalte | ✓ | 振り分け |
| 送客タイプ | 資料請求／相談予約／見積依頼 | ✓ | 対応の種類 |
| ステータス | 送客済／対応中／商談中／成約／不成立 | ✓ | 進捗・成果報酬判定 |
| 成約金額 | ¥1,200,000 | △（B以降） | 成果報酬の計算 |
| 成果報酬額 | ¥48,000 | △（B以降） | 請求 |
| 同意フラグ／取得日時 | 済 2026-06-01 | × | コンプライアンス |
| 友だちID | （Lステップ内部ID） | × | 追客・名寄せ |

## 5. ワンクリック・ボタンの中身（Lステップ設定）

送客ボタンを押すと、内部で順に実行：

1. **同意チェック**：タグ「同意_第三者提供」が「済」か確認。未なら1回だけ確認画面（同意で「済」に更新）。
2. **タグ付与**：例 `送客_アポ帳_iQalte_資料請求`（[`01`](./01-routing-priority-master.md) のカテゴリ体系に対応）。
3. **送客IDを発行**：`R-日付-連番`。
4. **Webhook転送**：医院カルテ情報＋カテゴリ＋IDを台帳・通知へ送信（リアルタイム）。
5. **先生へ自動返信**：「受付しました。担当者よりご連絡します」＋（任意で）資料PDFを即時送付。

### 送客タイプは3種類

| タイプ | 動き |
|---|---|
| **資料請求** | 登録情報を送客先へ＋（あれば）資料PDFを先生に即時送付。最も軽い1タップ |
| **相談予約** | 送客先の予約枠（または個別相談）へ誘導＋情報共有 |
| **見積依頼** | お悩みの要点だけ追加入力→送客先へ |

## 6. リアルタイム共有のやり方（送客先ごと）

### ① 専用ダッシュボード（件数をリアルタイム表示）
- 送客先ごとに **Looker Studio の専用リンク**（自社分だけ・閲覧専用）を発行。
- 表示内容：**今日／今月／累計の送客数**、内訳（資料請求／相談予約／見積依頼）、地域内訳、(フェーズB)成約数・成果報酬額。
- 更新は**数秒〜数分のニアリアルタイム**（Looker Studioのデータ更新間隔を最短に設定）。

### ② 即時通知（1件ごと）
- 送客が発生するたび、送客先の**メール／Chatwork／LINE WORKS／Slack**へ即通知。
- 通知に**送客ID・医院名・地域・お悩み・連絡先**を載せ、すぐ動けるように。

> ダッシュボード（全体の件数把握）＋通知（個別の即対応）の**二段構え**が最善。

---

## 7. 成果報酬を正しく取る仕組み（トラッキングの整合）

- **1送客＝ユニークID**で管理。さらに送客先には**専用LP／専用フォーム／クーポンコード**を割り当て、二重で紐付け。
- ステータスを **送客済→資料送付→商談中→成約→請求** と更新（フェーズBは送客先が入力、フェーズAはこちらが月次でヒアリング更新）。
- **月次でこちらの送客数 vs 先方の成約報告を突合**＝取りこぼし・申告漏れを防ぐ。
- この送客レポートが、**掲載料の値上げ・上位表示の入札**の交渉材料になる（[`01`](./01-routing-priority-master.md) §4）。

---

## 8. 課金モデルとの連動

| 課金形態 | ダッシュボードでの扱い |
|---|---|
| **掲載料（固定・月額）** | 枠を持つ送客先は常時表示。送客数レポートで価値を可視化 |
| **成果報酬（成約連動）** | ステータス「成約」に連動して**自動集計→請求**（フェーズB） |
| **ハイブリッド** | 掲載料（安）＋成果報酬。複数社が並ぶ枠は**入札で上位表示**を販売 |

## 9. プライバシー・法律（必ず守る）

- **第三者提供の同意**を医院カルテ登録時に取得（[`05`](./05-clinic-profile-questions.md) 質問15）。同意者のみ送客対象。
- 送客先に渡すのは**必要最小限の項目のみ**（連絡先は同意者に限定）。
- **プライバシーポリシーを更新**し、提供先・目的・範囲を明記。同意ログを保存。
- 送客先とは**秘密保持・データ取扱いの覚書**を交わす。

## 10. 必要なLステップのプラン / 機能

| 機能 | 必要なプラン | 用途 |
|---|---|---|
| **Webhook転送** | フリープランから**オプション**で可 | ボタン操作→外部へリアルタイム送信（フェーズAの中核） |
| **回答フォーム＋友だち情報差し込み** | 標準機能 | ワンクリック資料請求 |
| **API連携（外部→Lステップ書き戻し）** | **プロプラン以上**のオプション | 成約結果をタグへ反映（フェーズB） |

> 現在のプランで「Webhook転送」が有効かを最初に確認。フェーズBの書き戻しが必要になった段階でプロプランを検討。

## 11. ツール比較と推奨

| 用途 | 候補 | 推奨 | 理由 |
|---|---|---|---|
| つなぎ（自動化） | Make / Zapier / GAS | **Make** | 安価で柔軟、Webhook→Sheet→通知が得意 |
| 台帳 | Googleスプレッドシート / Airtable / Supabase | **A:スプレッドシート → B:Airtable** | まず無料で開始、拡張時にAirtable |
| 共有画面 | Looker Studio / スプレッドシート共有 / 専用ポータル | **Looker Studio** | 送客先別に閲覧専用でリアルタイム表示 |
| 通知 | メール / Chatwork / LINE WORKS / Slack | **送客先の常用ツールに合わせる** | 即対応してもらえる |

## 12. 最初の30日でやること（送客システム版）

1. **同意項目**を医院カルテに追加（[`05`](./05-clinic-profile-questions.md) 質問15）。
2. **送客台帳（スプレッドシート）＋送客ID採番**を用意。
3. **Make（またはGAS）**で「ボタン操作→台帳に追記→送客先へ通知」を**1カテゴリ（例：クラウドアポ帳）**だけ作る。
4. **Looker Studio**で送客先1社分の専用ダッシュボードを作って共有。
5. **送客先1社で試験運用**→件数表示と通知を確認→改善→他カテゴリへ横展開。
